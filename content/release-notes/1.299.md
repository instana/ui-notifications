## Features

The following features are added in release 1.0.299:

### Service levels

The Service levels dashboard can now be sorted according to the 'Status / target' column and filtered on Status, Tags, Blueprint and Entity.

For more information, see [Dashboard overview](https://www.ibm.com/docs/en/instana-observability/saas?topic=slos-service-level-objectives#dashboard-overview).

### Cassandra

The Tombstone metrics (marker indicating a deletion) are now included in the dashboards. 

For more information, see [Monitoring Cassandra](https://www.ibm.com/docs/en/instana-observability/saas?topic=technologies-monitoring-cassandra).

### Correction windows for Service levels

You can now configure Correction windows to temporarily pause error budget consumption for one or more Service Level Objectives (SLOs). During maintenance periods, latency and availability indicators for affected services are excluded from error budget calculations.

Correction windows can be set as one-time or recurring events. They can be scheduled in advance for planned outages or applied retroactively to correct the error budget for both planned and unplanned downtime that must not have impacted the error budget.

For more information, see [Service level objectives](https://www.ibm.com/docs/en/instana-observability/saas?topic=instana-service-level-objectives-slos).

### Impacted Users

The **Impacted Users** feature now supports Website and Mobile App Smart Alerts. This feature tracks the number of users who are affected by specific alert criteria, which helps you to identify widespread performance issues. 

This feature provides the following capabilities:

- Prioritize fixes to address the issues that impact many users first.
- Use quantifiable data to justify resource allocation for improvements.
- Assist developers focus on areas with the most frequent impact.

For more information, see [Website Smart Alerts](https://www.ibm.com/docs/en/instana-observability/saas?topic=websites-smart-alerts) and [Mobile App Smart Alerts](https://www.ibm.com/docs/en/instana-observability/saas?topic=applications-smart-alerts).

### Integration with AWS PrivateLink

The Instana integration with AWS PrivateLink is now generally available. With this integration, you can improve the stability, security, and cost of your application's data traffic with Instana. 

For more information, see [Integrating Instana with AWS PrivateLink](https://www.ibm.com/docs/en/instana-observability/saas?topic=apis-integrating-aws-privatelink).

### OpenTelemetry span events and span links (public preview)

You can now view OpenTelemetry span events and span links in the Instana UI if you set them in your OpenTelemetry trace.

For more information, see [OpenTelemetry span events and span links](https://www.ibm.com/docs/en/instana-observability/saas?topic=os-traces#opentelemetry-span-events-and-span-links).

### Synthetic monitoring: Support for '@ibm-cloud/secrets-manager'

Synthetic PoP JavaScript playback engine now supports the integration of `@ibm-cloud/secrets-manager`. 

### End user monitoring: Instana reporting for mobile app excessive background network usage.

You can now monitor excessive background network usage with the Instana Android agent. 

For more information, see [Performance metric for Excessive background network usage (ENU)](https://www.ibm.com/docs/en/instana-observability/saas?topic=applications-performance#performance-metric-for-excessive-background-network-usage-enu). 

### Screen rendering time for native Android and iOS mobile apps

You can now see the View transition time for each view in the Mobile app dashboard. View transition time shows the time taken for a mobile device to switch from one view to another. This feature is supported starting from Android agent version 6.2.2 and iOS version 1.9.2. To capture the View transition times, update your agent to a supported version and enable automatic view detection. 

For more information, see [View detection](https://www.ibm.com/docs/en/instana-observability/saas?topic=applications-auto-view-detection).

## Improvements

The following improvements are provided in release 1.0.299:

### Synthetic monitoring

- The Node.js version in Synthetic PoP JavaScript playback engine and BrowserScript playback engine is upgraded to v22. The Node.js version supports only the CommonJS module system.
- The [synctl](https://github.com/instana/synthetic-synctl) tool is enhanced to include the DNS test type in capacity planning.

### Windows Hyper-V 

The Windows Hyper-V dashboards are enhanced with new metrics for both host and virtual machine dashboards. 
For more information, see [Monitoring Windows Hyper-V (public preview)](https://www.ibm.com/docs/en/instana-observability/saas?topic=technologies-monitoring-windows-hyper-v-public-preview).

## Fixes

The following issues are fixed in release 1.0.299:

### Podman Image Name

Previously, the **Podman Image Name** call tag contained the image ID instead of the image name. This issue is now fixed.

### Synthetic monitoring

An error in the [synctl](https://github.com/instana/synthetic-synctl) tool prevented associating a test with applications whose IDs start with "-". This issue is now fixed.
