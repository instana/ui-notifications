## Features

The following features are added in release 1.0.311:

### Adaptive threshold support for Log Smart Alerts

Log Smart Alerts now support adaptive thresholds in addition to static thresholds. Adaptive thresholds continuously evolve and adjust themselves based on new data observed by Instana, continuously accounting for seasonal changes in log metrics without manual intervention. The baseline is updated gradually as more data is received over time. This feature requires at least 12 hours of continuous metric data to initialize the model.

For more information, see [Smart Alerts for logs](https://www.ibm.com/docs/en/instana-observability/saas?topic=logging-smart-alerts#smart_alerts__defining-the-threshold__title__1).

### Control plane monitoring in Kubernetes clusters

The cluster dashboard displays the Kubernetes control plane components and shows detailed metrics for each component.

For more information, see [Control plane monitoring](https://www.ibm.com/docs/en/instana-observability/saas?topic=instana-monitoring-kubernetes#concept_1__title__1).

## Improvements

The following improvements are provided in release 1.0.311:

### Programming language detection for OpenTelemetry spans

Instana now automatically detects and tags the programming language or runtime for OpenTelemetry spans (Java/JVM, Node.js, Python, Go, .NET, PHP, and Ruby) by using the `telemetry.sdk.language` resource attribute, improving service filtering and technology mapping.

### Resource attributes in OpenTelemetry dashboards

The OpenTelemetry default dashboards now display monitored resource attributes, providing consistent contextual information across dashboard types. This enhancement improves resource visibility and supports better troubleshooting.

### OpenTelemetry Kubernetes uptime metrics

The OpenTelemetry Collector Helm configuration for DaemonSet mode now includes uptime metrics for Kubernetes nodes and pods. The following metrics are now enabled by default in the `kubeletstats` receiver:
- `k8s.node.uptime`: Tracks node uptime
- `k8s.pod.uptime`: Tracks pod uptime

These metrics provide better visibility into the operational status and stability of Kubernetes infrastructure components when you use OpenTelemetry for monitoring.

### Adding Count and Message count metrics

**Count** of entities and **Message count** metrics are available in analyze infrastructure, custom dashboards, and Smart Alerts.

The Count metric represents the number of entities for a specific plugin, while the Message count metric provides the number of messages sent to the backend. You can filter these metrics and group them by tags, enabling use cases, such as alerting on the number of JVMs running on hosts within a specific availability zone.

## Fixes

The following issues are fixed in release 1.0.311:

### Resilient service mapping

[Resilient service mapping](https://www.ibm.com/docs/en/instana-observability/saas?topic=applications-services#why-does-the-service-name-sometimes-change__title__1) uses cached results to map calls to services when infrastructure data is missing or incomplete. Previously, cached service names were applied even when they had the same priority as the current [mapping rule](https://www.ibm.com/docs/en/instana-observability/saas?topic=applications-services#predefined-rules__title__1), which could occasionally lead to incorrect service assignments. Now, cached names are used only when they come from higher-priority mapping rules, which reduces false positives.

### SAP Solution Manager integration

Instana no longer supports Integration via SAP Solution Manager (SolMan). You can now monitor the SAP ABAP, Java NetWeaver application servers, and HANA database by using native Instana [sensors](https://www.ibm.com/docs/en/instana-observability/saas?topic=technologies-monitoring-sap).

### Windows Communication Foundation (WCF) calls
Fixed an issue that prevented filtering or grouping by error message for Windows Communication Foundation (WCF) calls.

### Synthetic monitoring

The following security vulnerabilities are fixed on Synthetic PoP:
- CVE-2024-21147
- CVE-2025-67735
