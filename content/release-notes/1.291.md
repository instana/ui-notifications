## Features

### StatsD tagged metrics

You can now use [StatsD](../../ecosystem/statsd/index.md) metric tags to filter and group metrics in **Analyze Infrastructure** and **Custom Dashboards**.

### LangChain monitoring

Instana now supports monitoring LangChain. To monitor LangChain, export traces and metrics from your LangChain application to Instana. For more information, see [Monitoring AI Agents](../../ecosystem/gen-ai-observability/ai-agents/index.md).

### LangGraph monitoring

Instana now supports monitoring LangGraph. To monitor LangGraph, export traces and metrics from your LangGraph application to Instana. For more information, see [Monitoring AI Agents](../../ecosystem/gen-ai-observability/ai-agents/index.md).

### Closing multiple issues and incidents

You can use the multi-close feature to simultaneously close multiple issues and incidents. By using the multi-close feature, you can streamline workflows and improve operational efficiency. For more information, see [Multi-closing issues and incidents](../../events_alerts/multi-close.md).

### Installing the Instana agent on Red Hat OpenShift on z/OS

You can now install the Instana agent on Red Hat OpenShift Container Platform on IBM z/OS by using the IBM z/OS Container Extensions (zCX). For more information, see [Installing the agent on Red Hat OpenShift on IBM z/OS by using IBM z/OS Container Extensions](../../setup_and_manage/host_agent/on/openshift-zCX.md).

## Improvements


### API for triggering notification manually

Previously, notifications triggered with an API were limited to events within the current month. This restriction is now removed. For more information, see [API for triggering notification manually](../../events_alerts/notify-api.md).

### Collecting machineId on Linux, macOS, and Windows systems

The Instana Host sensor now collects machineId on Linux, macOS, and Windows systems. The machineId is used to correlate OpenTelemetry entities with Host entities.

### Automation action snapshot details

The **Properties** tab of **Action History** now has an **Action snapshot details** section, which displays the details of the action at the time of execution.

### Synthetic monitoring

- The **Record user actions on failure** option is available when you create or edit a Browser Simple or a Browser Script test in **Advanced Mode**. By default, the **Record user actions on failure** option is disabled.
- **Custom properties**, a new section is added in the test results details page. This section displays the custom properties that are defined in the corresponding Synthetic test.


## Fixes

### Rounding of values using SI prefix

Values show in [SI format](https://en.wikipedia.org/wiki/International_System_of_Units) were rounded down instead of rounded to the closest value. A value of `14.57` was previously formatted using a SI prefix with zero decimal place as `14` instead of `15`. Likewise, a value of `1567` would be formatted as `1.5k` instead of `1.6k`.

The number of decimal places is also made more consistent when using a SI prefix, such that places that should show 2 decimal values strictly show 2 decimal values. This previously could have shown more or fewer values. For example when formatting `433.123` using a SI prefix with one decimal place, the value was `433.123` instead of `433.1`.

These errors were limited only to the SI prefix formatter.

### Synthetic monitoring

- The security vulnerability, CVE-2025-24970 is fixed in Synthetic PoP.
- The inconsistent custom-properties format across create, update, and patch a test operations is fixed in the [synctl](https://github.com/instana/synthetic-synctl){: external}![External link icon](../../../assets/images/new_window.svg "Opens in a new tab or window") tool. Not to break the existing automation, the old format is marked as deprecated.

### Time Range configuration resets to default value

Previously, when users set a specific **Time Range** configuration and go to **Analytics** by using the navigation menu, the system resets the time configuration to its default value. This issue is now fixed.
