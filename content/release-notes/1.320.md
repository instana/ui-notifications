## Features

The following features are added in release 1.0.320:

### Apdex Smart Alerts

You can now create Smart Alerts for Apdex configurations to monitor user satisfaction. The Smart Alerts tab on the Service levels
dashboard displays both SLO and Apdex Smart Alerts with filter-based separation. A dedicated Smart Alerts tab is also available on
individual Apdex dashboards. For more information,
see [Smart Alerts for service levels]( https://www.ibm.com/docs/en/instana-observability/latest?topic=slos-smart-alerts-service-level-objectives).

### Infrastructure data granularity plugin percentage breakdown

A **View details** button is added to the **Infrastructure** field on the "Accounts & billing" dashboard. It displays a modal with
the percentage breakdown of the top 10 entities by bytes ingested for each plug-in. This feature helps you identify the entities
that contribute the most to data ingestion. For more information,
see [Infrastructure]( https://www.ibm.com/docs/en/instana-observability/latest?topic=instana-viewing-data-usage-billing#ariaid-title6).

### Multiple metrics in Analyze infrastructure exploration chart

You can now select up to 3 chart metrics in **Analyze infrastructure** to view multiple aggregated metric values across filtered
entities at the same time. For more information,
see [Analyze Infrastructure](https://www.ibm.com/docs/en/instana-observability?topic=analytics-analyze-infrastructure).

### Windows MSI installer for Instana Distribution of OpenTelemetry Collector (IDOT) (Public Preview)

IDOT is now available as a Windows MSI installer package. The MSI (Microsoft Installer) provides a standardized, enterprise-ready installation experience for Windows environments. It supports both interactive GUI and silent command-line installations.

The installer automatically configures the Instana Collector Service as a Windows service and supports automated deployments through enterprise tools, such as Group Policy and System Center Configuration Manager (SCCM). For more information, see [Installing IDOT on Windows by using the MSI installer.]( https://www.ibm.com/docs/en/instana-observability/latest?topic=idot-installing-windows-by-using-msi-installer).

## Improvements

The following improvements are provided in release 1.0.320:

### DBmarlin integration for ADO.NET calls

DBmarlin database integration now supports ADO.NET calls. If you configure and enable a DBmarlin database integration, the **Find SQL in DBMARLIN** button also appears in the trace detail view for ADO.NET calls.

### Infrastructure tag catalog search

Improved search behavior in the Infrastructure tag catalog. Previously, search results were returned if they matched any of the
search tokens. Now, the search returns only results that match all specified tokens.

### Infrastructure tags synchronization

Improved the reliability of infrastructure tag synchronization. Previously, infrastructure tags might occasionally become out of
sync with entities, leading to incorrect results in **Analyze infrastructure** and **Custom dashboards**. Now, the synchronization
process is more resilient and improves data consistency.

### Navigation to graph explorer

You can now navigate directly from infrastructure dashboards to graph explorer by using the **View in graph explorer** button. For
more information,
see [Graph explorer](https://www.ibm.com/docs/en/instana-observability/infrastructure-graph-explorer#GUID-90b35768-6947-4e7f-a00e-8a23e07ef29d__section_1__title__1).

### OpenTelemetry traces

Improved the rendering of OpenTelemetry spans for HTTP, messaging, RPC, and database calls.

### vLLM infrastructure metrics with IDOT and OTel collector

You can now view vLLM metrics in infrastructure across your stack in Instana by using open source OpenTelemetry collectors. Instana Distribution of OpenTelemetry Collector (IDOT) and specialized OTel Data Collector for vLLM (ODCV) collector are supported.

## Fixes

The following issues are fixed in release 1.0.320:

### Application Perspectives with no calls shown in the Applications list

The Applications list now correctly displays Application Perspectives even when no calls are detected within the selected time frame.

### Application Stack dropdown lists unrelated services

Fixed an issue where the **Stack** dropdown in an application dashboard displayed all services instead of filtering the service list by the current application.

### Missing resource attributes for OpenTelemetry calls

Fixed an issue where OpenTelemetry calls that are linked to infrastructure entities were missing resource attributes from spans.

### Saved metrics in the Analyze infrastructure

Fixed an issue where metrics that were part of saved queries in **Analyze infrastructure** were not applied correctly.

### Service APIs ignore application ID filter

Fixed an issue where the following APIs ignored the application ID in requests:

- `/api/application-monitoring/metrics/services?includeSnapshotIds=true`
- `/api/application-monitoring/applications;id=<appId>/services`

These APIs now correctly filter and return results based on the specified application ID.

### Services with no calls not displayed in the service list

Resolved an issue where services with no calls in the selected timeframe were missing from the service list in the Applications area. The service list now includes services detected from infrastructure entities, even if they received no actual calls.
