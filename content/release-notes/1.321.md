Release date: 13 July 2026

Instana delivers new and improved features and user experience with each release. Review the following details about the latest release to learn what's new and changed with Instana 1.0.321:

## Features

The following features are added in release 1.0.321:

### Business impact for websites

The **Business impact** tab for websites now includes a **Conversion goals** list. The list displays the five conversion goals with the highest conversion rates. You can switch between the **Sessions** and **Users** views.

### Centralized business view dashboard

Instana introduces a centralized business view dashboard (BVD) that provides a single, unified view of key business and operational metrics. It includes application growth, SLO compliance, incident resolution performance, and platform consumption (such as data usage and MVS capacity), along with month-over-month trends and forecasting insights.

### Streamline observability data access with GraphQL

Instana now offers GraphQL, which provides a faster and more flexible way to query observability data. With GraphQL, you can retrieve exactly the data you need in a single request, apply multiple levels of filtering, and access metrics, traces, and logs through a single endpoint. You no longer need to make multiple calls or process excess data that traditional REST APIs return. In addition, GraphQL simplifies integrations with dashboards and automation workflows. You can build queries that match your exact data requirements, which accelerates development cycles and reduces over-fetching.

### Enable tag support for Azure virtual machines

The Instana agent now collects tags from metadata of Azure virtual machines and applies them to both Azure instance entities and corresponding host entities. This update improves visibility and organization across Azure infrastructure.

### End user monitoring: Dependency view call analytics

You can now view call analytics for nodes within the dependency graph for websites and mobile apps.

The call analytics include:

- Calls from the root node to all service nodes
- Calls from the root node to a specific service node

These insights help you better understand service dependencies and quickly identify performance bottlenecks. For more information, see [Viewing service dependencies for mobile applications](https://www.ibm.com/docs/en/instana-observability/latest?topic=monitoring-viewing-service-dependencies-mobile-applications) and [Viewing service dependencies for websites](https://www.ibm.com/docs/en/instana-observability/latest?topic=monitoring-viewing-service-dependencies-websites).

### Enhanced visibility for Argo Rollouts

Added preview support for Argo Rollouts that enables automatic discovery, monitors rollout resources, and displays rollout status and deployment progress for improved visibility.

### ICMP ping tests for synthetic monitoring

Now Instana supports Internet Control Message Protocol (ICMP) ping test for synthetic monitoring. You can check network reachability and measure latency by sending ping requests to a target host. For more information, see [Monitoring endpoints with Synthetic tests](https://www.ibm.com/docs/en/instana-observability/latest?topic=monitoring-endpoints-synthetic-tests).

You need to upgrade the Synthetic PoP to 1.2.48 to obtain support for the new ICMP capability.

### Microsoft Playwright support on synthetic browser script tests

Browser script tests now support Microsoft Playwright, enabling advanced browser automation. For more information, see [Using browser scripts](https://www.ibm.com/docs/en/instana-observability/latest?topic=scripts-using-browser).

You must upgrade Synthetic PoP to 1.2.48 for Microsoft Playwright to work.

### Integration with IBM Concert Network Observability

Instana now integrates with IBM Concert Network Observability. You can view pod-to-pod network Round-Trip Time (RTT) metrics for Kubernetes applications directly within the Instana service flow visualization. This enhanced visibility helps you identify whether performance issues originate from the network or application layer. For more information, see [Integrating with IBM Concert Network Observability](https://www.ibm.com/docs/en/instana-observability/latest?topic=products-integrating-concert-network-observability).

### Mobile app Service Level Objectives

Instana now supports Service Level Objectives (SLOs) for mobile applications. You can monitor mobile app performance by using beacon data from HTTP requests, sessions starts, view transitions, crashes and custom events. You can configure SLOs with dynamic metric selection based on blueprint type and beacon type. You can select individual apps or use filter-based selection with platform, country, device model, and other attributes.

### Smart Alert hub

The Smart Alert hub now supports multi-select entity type filtering, allowing you to select multiple entity types and view Smart Alert configurations across those selected types in a single consolidated list. For more information, see [Smart Alert configurations hub](https://www.ibm.com/docs/en/instana-observability/latest?topic=alerts-smart-alert-configurations-hub).

### Smart Alerts for infrastructure multi-metric support

Instana now supports infrastructure Smart Alerts that can monitor multiple metrics simultaneously.

The infrastructure Smart Alert creation dialog is also improved to use a Carbon-based user interface, providing a wider step-by-step workflow for configuring alerts.

### Regular expression support in Analyze Infrastructure metrics selector

The **Add metric** selector in **Analyze Infrastructure** now supports regular expressions. For more information, see [Analyze Infrastructure](../../analyze_infrastructure/index.md).

## Improvements

The following improvements are provided in release 1.0.321:

### Batch update and deletion for Synthetic tests

Bulk operations are now supported, allowing users to select multiple Synthetic tests from the Synthetic Monitoring test page to delete or update them at once. For more information, see [The Synthetic tests tab](https://www.ibm.com/docs/en/instana-observability/latest?topic=ui-synthetic-tests-tab).

### Changes to agent version terminology

Updated the agent version terminology to improve clarity and align with the agent's architecture:

- **Agent version**: Refers to the static installed part of the agent, including the runtime and other non-updating components. Previously called "Boot version".
- **Sensors version**: Refers to the dynamic sensors update version, including the BOM for sensors and tracers. Previously called "Agent version".

This terminology change is reflected throughout the Instana documentation and user interface to provide a clearer distinction between the static agent runtime and the dynamically updated sensor components.

### New entity fields for agent versioning

Added the following new entity fields to align with the updated agent version terminology:

- `entity.agent.agentVersion`: Static agent version (maps to boot version data).
- `entity.agent.sensorsVersion`: Dynamic sensors version (maps to agent version data).

These fields provide clearer access to version information in queries, dashboards, and API calls, making it easier to distinguish between the static agent runtime version and the dynamically updated sensors version.

### Google Cloud Platform (GCP) label support

Instana now supports automatic collection of labels for the following GCP services:

- Google Cloud Pub/Sub: Instana automatically collects labels from Pub/Sub topics and subscriptions. You can view these labels in the **Tags** section and use them for filtering on the **Infrastructure** map.

- Google Cloud Run: Instana automatically collects labels from Cloud Run service revisions. You can view these labels in the **Tags** section and use them for filtering on the **Infrastructure** map.

### OMEGAMON z/OS Db2 monitoring

The z/OS Db2 dashboard displays expanded metrics and improved visualizations. You can monitor buffer pools, locks, logs, SQL statistics, EDM pool, and SRM subsystem performance. The dashboard also shows improved z/OS system statistics, including CPU utilization metrics.
**Prerequisite:** This enhancement requires Instana host agent version 2026.06.02.1428 or later.

### Enhanced AI gateway management and access control

Users with the required role-based access control (RBAC) permissions can enable or disable individual AI gateways. They can also disable all gateways to disconnect large language models (LLMs) from Instana. Administrators can use RBAC to control which users can access and manage generative AI features.

The core causal AI engine in Instana operates independently of AI gateway status and is not affected by these settings. For more information, see [AI Gateway configuration](https://www.ibm.com/docs/en/instana-observability/latest?topic=gateway-ai-configuration).

### Improved visibility of services with only internal or outgoing calls

The main services list on the **Services** tab in the **Applications** area now includes services that report only internal or outgoing calls, even when no incoming external (cross-service) calls are reported.
Service call metrics continue to be calculated based on incoming external (cross-service) calls to a service. As a result, these services appear with 0 calls in the main services list and remain excluded from the scoped services list for applications.

### Automated triggering of intelligent incident investigations

You can now run an intelligent incident investigation automatically by using REST API or by configuring an Automated Action on an application Smart Alert policy, which enables a zero-touch incident investigation as part of your incident response workflow. For more information, see [Automatically triggering investigations](../../intelligent_incident_investigation/intelligent-incident-investigation.md#automatically-triggering-investigations).

### Smart Alerts for logging UI changes

The UI dialogs for creating Smart Alerts for logging are replaced with a new Carbon-based user interface. With this improved UI, you can now configure Smart Alerts for logging in a wider step-by-step workflow view.

### Log volume relocation and redesign

The log volume report is now available under **Account & billing** > **Data granularity** > **Log messages** and includes a redesigned user interface. For more information, see [Viewing log volume report](https://www.ibm.com/docs/en/instana-observability/latest?topic=logging-viewing-log-volume-report).

### Fast query mode on logs

Fast query mode now returns more precise results for time windows of less than an hour.
