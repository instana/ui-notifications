## Features

The following features are added in release 1.0.326:

### Filter the physical infrastructure map by erroneous entities

You can now filter the physical infrastructure map to display only erroneous entities. Click the **Show erroneous entities only** icon in the overlay controls to hide healthy hosts and layers. The map also displays healthy hosts that contain at least one erroneous layer. Click the icon again to restore the full map.

For more information, see [Show erroneous entities only](https://www.ibm.com/docs/en/instana-observability/saas?topic=infrastructure-map#show-erroneous-entities-only__title__1).

### Guided onboarding for Generative AI Observability

You can now use a guided onboarding experience in the Instana UI to generate tailored setup instructions for monitoring Gen AI applications in your environment.

For more information, see [Guided onboarding for Gen AI monitoring](https://www.ibm.com/docs/en/instana-observability/saas?topic=observability-getting-started#index__section_guided_onboarding__title__1).

### Monitoring Cilium (public preview)

Instana now supports monitoring network traffic details from Cilium as a public preview feature when Cilium is configured as the Container Network Interface (CNI) plug-in in Kubernetes environments. This capability provides visibility into traffic flows, L4 transport health, DNS queries, HTTP metrics, and Cilium agent metrics across Kubernetes workloads.

For more information, see [Monitoring Cilium (public preview)](https://www.ibm.com/docs/en/instana-observability/saas?topic=kubernetes-monitoring-cilium-public-preview).

### Range operators for Log Smart Alert thresholds

Log Smart Alerts support range operators for both static and adaptive thresholds. For static thresholds, use the `Between` operator to trigger an alert when the log count falls within a configured range, or the `Outside` operator to trigger an alert when it falls outside that range. For adaptive thresholds, use the `Outside` operator to trigger an alert when the log count falls outside the predicted range.

For more information, see [Smart Alerts for logs](https://www.ibm.com/docs/en/instana-observability/saas?topic=logging-smart-alerts).

### Service level objectives: Health score and health state summary

Service level objectives (SLOs) now include a **Health score** and a summary grid on the SLO dashboard. Instana evaluates error budget consumption, active burn rates, and trends in real time to display a 0–100 health score, health states, and diagnostic reasons that help you identify reliability risks before the error budget is exhausted.

For more information, see [SLO health state summary](https://www.ibm.com/docs/en/instana-observability/saas?topic=slos-service-level-objectives#slo-details__slo-health-state-summary__title__1).

### Synthetic monitoring: Multi-location threshold for Smart alerts

You can now configure Smart Alerts for synthetic monitoring to require failures from multiple separate locations before the system triggers an alert. You can set a minimum number of locations and a time window within which those failures must occur. This multi-location threshold feature reduces alert noise and focuses alerts on problems that affect multiple users rather than a single location.

In **Configure alert**, specify the number of locations and the number of consecutive failures that are required per location to trigger the alert.

If the location count you set exceeds the number of locations that are configured for any test in scope, that test can never trigger the alert. Verify that all tests in scope use at least as many locations as the threshold you specify.

For more information, see [Configuring alerts](https://www.ibm.com/docs/en/instana-observability/saas?topic=monitoring-setting-smart-alerts-synthetic-tests#concept_3).

## Improvements

The following improvements are provided in release 1.0.326:

### Changed "Analyze calls" links from endpoint dashboards

The **Analyze calls** links from an endpoint dashboard and its KPI cards to unbounded analytics no longer add a default grouping. Previously, these links added a grouping by **Call name**, but because this tag does not support efficient preaggregation, this grouping can produce approximate results that differ from the exact data that is displayed in the endpoint dashboard.

You can still manually group by **Call name** in the resulting unbounded analytics page. However, doing so might reduce the accuracy of the displayed results.

### Chrome upgrade for the Synthetic PoP BrowserScript engine

The Synthetic Point of Presence (PoP) BrowserScript playback engine is updated from Chrome 113 to Chrome 144. This update resolves several high-severity Common Vulnerabilities and Exposures (CVEs).

Chrome can deprecate features between major versions. Because of this version change (113 to 144), review the [Chrome release notes](https://developer.chrome.com/release-notes) for deprecated features that might affect your browser-based synthetic tests.
{: important}

### Direct UI URLs in Smart Alert and custom event API responses

Smart Alert configuration and custom event specification API responses include a read-only `displayUrl` property. API users can use this absolute URL to open the corresponding configuration directly in the Instana UI.

For more information, see [OpenAPI](https://instana.github.io/openapi/).

### OMEGAMON monitoring enhancements

You can now access the following OMEGAMON monitoring enhancements:

- The z/OS Db2 dashboard now includes an **Address Spaces** table that shows MVS storage usage per Db2 address space.
- The z/OS IMS dashboard includes new tables: **Databases**, **Transactions**, **Shared queues**, **Lock conflicts**, **RTA group slots**, **Logical terminals**, and **External subsystems**, along with additional KPI metrics.

**Prerequisites:** Both enhancements require Instana host agent 2026.09.15.1111 or later. If you use a filters file to filter product tables in `connect.yaml`, you must update it with the additional product tables.

For details, see [Configuring OMEGAMON data connect](https://www.ibm.com/docs/en/instana-observability/saas?topic=technologies-monitoring-omegamon#prerequisites__configuring-omegamon-data-connect).

### Duplicate synthetic tests from the test list

You can now view the **Duplicate Test** action in the **Actions** column on the **Synthetic tests** page.

The **Duplicate Test** action helps you to copy an existing synthetic test to reuse configurations and create similar tests.


### Enhanced bulk editing for synthetic tests

The **Bulk Edit** window provides greater flexibility when you update multiple synthetic tests. When all selected tests share the same test type, you can add and modify type-specific fields across the selected tests.

The **Bulk Edit** window also supports multi-select deletion across all tables, so you can remove multiple entries in a single action.

### Redesigned Edit Synthetic Test experience

The updated **Edit Synthetic Test** dialog provides an improved user experience. You can navigate between configuration sections and update settings in any order without following a predefined sequence.


### Synthetic Results Dashboard enhancements

The **Synthetic Results Dashboard** now includes a dedicated **Logs** tab that separates test execution details from log data.

The dashboard includes the following tabs:

- **Summary**: Displays test execution details and result information.
- **Logs**: Displays both console logs and browser logs for the selected test execution.
