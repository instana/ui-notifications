## Features

The following features are added in release 1.0.326:

### Monitoring Cilium (public preview)

Instana now supports monitoring network traffic details from [Cilium](https://cilium.io/) as a public preview feature when Cilium is configured as the Container Network Interface (CNI) plugin in Kubernetes environments. This capability provides visibility into traffic flows, L4 transport health, DNS queries, HTTP metrics, and Cilium agent metrics across Kubernetes workloads.

For more information, see [Monitoring Cilium (public preview)](../../ecosystem/kubernetes/cilium-monitoring.md).

### Filter the physical infrastructure map by erroneous entities

You can now filter the physical infrastructure map to display only erroneous entities. Click the **Show erroneous entities only** icon in the overlay controls to hide healthy hosts and layers. The map also displays healthy hosts that contain at least one erroneous layer. Click the icon again to restore the full map.

For more information, see [Show erroneous entities only](../../infrastructure_monitoring/infrastructure-map.md#show-erroneous-entities-only).

### Service level objectives: Health score and health state summary

Service level objectives (SLOs) now include a **Health score** and summary grid on the SLO dashboard. Instana evaluates error budget consumption, active burn rates, and trends in real time to display a 0–100 health score, health states, and diagnostic reasons that help you identify reliability risks before the error budget is exhausted. For more information, see [SLO health state summary](../../service_level_objectives/slo_capabilities.md#slo-health-state-summary).

### Synthetic monitoring: Multi-location threshold for Smart alerts

You can now configure Smart Alerts for synthetic monitoring to require failures from multiple separate locations before the system triggers an alert. You can set a minimum number of locations and a time window within which those failures must occur. This multi-location threshold feature reduces alert noise and focuses alerts on problems that affect multiple users rather than a single location.

You must set the number of locations and the number of consecutive failures required per location in **Configure alert** to trigger the alert.

If the location count you set exceeds the number of locations configured for any test in scope, that test can never trigger the alert. Verify that all tests in scope use at least as many locations as the threshold you specify.

For more information, see [Configure alert](../../synthetic_monitoring/smart_alerts.md#configure-alert).

### Range operators for Log Smart Alert thresholds

Log Smart Alerts support range operators for both static and adaptive thresholds. For static thresholds, use the Between operator to trigger an alert when the log count falls within a configured range, or the Outside operator to trigger an alert when the log count falls outside that range. For adaptive thresholds, use the Outside operator to trigger an alert when the log count falls outside the predicted range. For more information, see [Smart Alerts for logs](../../logging/smart_alerts.md).

## Improvements

The following improvements are provided in release 1.0.326:

### Direct UI URLs in Smart Alert and custom event API responses

Smart Alert configuration and custom event specification API responses include a read-only `displayUrl` property. API users can use this absolute URL to open the corresponding configuration directly in the Instana UI. For more information, see [OpenAPI](https://instana.github.io/openapi/).

### Changed "Analyze calls" links from endpoint dashboards

The **Analyze calls** links leading from an endpoint dashboard and its KPI cards to unbounded analytics no longer add a default grouping. Previously, these links added a grouping by **Call name**; however, that tag does not support efficient pre-aggregation, and therefore grouping by call name can produce approximated results that differ from the exact data shown in the endpoint dashboard.

You can still manually group by call name in the resulting unbounded analytics page, if that is the breakdown you want to analyze, but adding this grouping may lead to less accurate results.

### OMEGAMON monitoring enhancements

This release adds the following enhancements to OMEGAMON monitoring:
- The z/OS Db2 dashboard now includes an **Address Spaces** table that shows MVS storage usage per Db2 address space.
- The z/OS IMS dashboard includes new tables: Databases, Transactions, Shared queues, Lock conflicts, RTA group slots, Logical terminals, and External subsystems, along with additional KPI metrics.

**Prerequisites:** Both enhancements require Instana host agent version 2026.09.15.1111 or later. If you use a filters file to filter product tables in `connect.yaml`, you must update it with the additional product tables. For details, see [Configuring OMEGAMON data connect](../../ecosystem/omegamon/index.md#configuring-omegamon-data-connect).
