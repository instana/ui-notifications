## Features

The following features are added in release 1.0.317:

### AI-powered SLO analysis

Service Level Objectives (SLOs) now include AI-powered summarization capabilities that help you quickly understand SLO performance and identify actionable insights.
The AI summarization feature provides two views:
- **Summary view**: Provides a concise executive summary that includes the SLO name, target percentage, current SLI value, error budget status, and compliance status.
- **Full details view**: Provides comprehensive analysis with SLO overview, entity context, performance status, key insights, and recommendations.
You can copy the summary text to the clipboard in both views. In the full details view, you can also download the summary as a PDF document for sharing or archival purposes. For more information, see [AI-powered SLO analysis](https://www.ibm.com/docs/en/instana-observability/current?topic=slos-service-level-objectives).

### Change agent mode API

You can now change the agent mode for a single agent or groups of agents by using the API endpoints `{unit}-{tenant}.instana.io/api/host-agent/{hostId}/mode` and `{unit}-{tenant}.instana.io/api/host-agent/mode`.

This feature allows teams to quickly switch agents to `APM`, `INFRA / INFRASTRUCTURE`, or `OFF` for operational response, troubleshooting, or to prevent host disruption.

The existing RBAC permission `Configuration of agent mode` controls access to this feature.

### Roles and permissions to access generative AI capabilities

A new permission is added to control access to generative AI capabilities in Instana. Administrators can now grant or restrict access to these AI features at the role level. For more information, see [Managing user access](https://www.ibm.com/docs/en/instana-observability/current?topic=instana-managing-user-access).


## Improvements

The following improvements are provided in release 1.0.317:

### Categorization of agent tags

Agent tags in Analyze Infrastructure are now grouped under the **Agent** category. This enhancement ensures consistency with Unbounded Analytics.

### Extended data retention configuration for self-hosted monitoring

Self-hosted installations now support more options to configure data retention of applications and end user monitoring:
- You can now reduce short-term full-data retention to as few as 2 days, in addition to increasing it from the default of 7 days.
- You can now configure long-term sampled data retention and reduce it from the 396-day default.

These configuration options help you reduce application database disk usage when you need only shorter time ranges for analysis.

### Improved search for ingestion data

You can now search and retrieve ingestion data beyond the first 10 results in data granularity tables for services, endpoints, EUM websites, mobile applications, and synthetic tests.

### Smart alerts on entity count

Smart alerts now support alerting on entity count.


## Fixes

The following issues are fixed in release 1.0.317:

### Correlation of calls with infrastructure

Under specific conditions, application monitoring did not correlate HTTP calls that used nondefault ports with the monitored infrastructure. This issue is now fixed.

### Removed static YAML installation option for Kubernetes and Red Hat OpenShift

The option to Install the agent by using static YAML files on Kubernetes or Red Hat OpenShift is removed from the Instana UI. These options were deprecated in March 2025.
