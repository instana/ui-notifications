## Features

The following features are added:

### Dynamic synthetic test SLO using scope filters

Synthetic test Service Level Objectives (SLOs) now support two methods for defining the scope of synthetic tests:
- **Individual test selection**: Select specific tests manually.
- **Filter-based selection**: Define scope by using filters to dynamically include all synthetic tests that match specified criteria.

The synthetic test selection dialog now includes the following enhancements:
- Filter tests by attributes such as location and type.
- Select multiple tests directly from search results.

For more information, see [Service level objectives](https://www.ibm.com/docs/en/instana-observability/latest?topic=slos-service-level-objectives).

### Apdex as a top-level feature
Apdex is now available as a top-level feature in the Service Levels section with its own dedicated tab. You can create, manage, and monitor Apdex configurations for both application perspectives and websites through a comprehensive dashboard interface.

The new multi-step configuration wizard provides granular control over scope, including the following elements:
- Call boundaries
- Filters
- Latency thresholds

Apdex configurations integrate with application and website dashboards and support custom dashboard widgets.

 For more information, see [Apdex](https://www.ibm.com/docs/en/instana-observability/latest?topic=legacy-using-apdex).

### Agent configuration download

Users can now download agent configurations for backup, audit, or troubleshooting purposes from the Agent Management Dashboard or by using the API endpoint `{unit}-{tenant}.instana.io/api/host-agent/{hostId}/configuration`.

The new RBAC permission "Can download agent configuration" controls access to this feature. Administrators can assign this permission to roles that need this capability.

### Infrastructure data usage volume breakdown

You can now view the breakdown of infrastructure data usage volumes in the **Data granularity** section of the **Account & billing** dashboard.

For more information, see [Viewing data usage and billing](https://www.ibm.com/docs/en/instana-observability/latest?topic=instana-viewing-data-usage-billing).

### Agent configuration download

Users can now download agent configurations for backup, audit, or troubleshooting purposes from the Agent Management Dashboard or by using the API endpoint `{unit}-{tenant}.instana.io/api/host-agent/{hostId}/configuration`.

The new RBAC permission "Can download agent configuration" controls access to this feature. Administrators can assign this permission to roles that need this capability.

### IP address filtering

Now you can deny or allow access to specific IP ranges on Instana by creating filtering rules. IP filtering provides network-level access control for API endpoints and the UI client. For more information, see [Configuring IP address filtering](https://www.ibm.com/docs/en/SSE1JP5_1.0.316/src/pages/admin/IP-filtering/Configure_ip_filtering.html).

## Improvements

The following improvements are provided in release 1.0.316:

### Flow map for business processes

Added a warning and error icon to process activity nodes to provide a clear visual indication of unhealthy activities.

### Filtering and grouping calls by IDs in unbounded analytics

You can now filter and group calls in the Analytics Applications Calls dashboard by using ID fields. Filtering is supported using Call ID and Parent Call ID that were previously available only as internal tags, and grouping is supported using Trace ID and Parent Call ID.

### Viewing Azure subscription ID

In the Instana UI, the **Infrastructure** map now displays the Subscription ID for Azure resources, such as Key Vault, Managed HSM, and Service Bus entities (Queues and Topics).

### AWS Metric Stream support for additional AWS services

AWS Metric Streams integration now supports additional AWS services:

- **Amazon Bedrock**: Observe foundation model metrics that use the `ModelId` dimension
- **Amazon CloudFront**: Monitor CDN metrics that use the `DistributionId` dimension
- **Amazon DocumentDB**: Track cluster or instance metrics that use `DBClusterIdentifier` and `DBInstanceIdentifier` dimensions
- **Amazon MQ**: Monitor message brokers that use the `Broker` dimension

### Pinned plug-ins for running components
Running components are displayed on infrastructure entity sidebars. They show the most detailed level of running components within the current entity. The following enclosing entities are pinned so that they are displayed with their children:
- AceIntegrationServer
- IbmIOs
- IbmMqQueueManager

### Shortened expiration delays for high poll rates
In previous releases, the time before an entity was marked offline was directly proportional to its poll rate. For example, with a poll rate of 60 seconds, the entity was considered offline 20 minutes after it actually went offline.
In the current release, the expiration delay is calculated as follows:
- For poll rates below 15 seconds, the delay is 20 times the poll rate.
- For poll rates of 15 seconds or higher, the delay is 5 times the poll rate.
As a result, with a poll rate of 60 seconds, Instana now considers the entity offline after 5 minutes.

## Fixes

The following issues are fixed:

### Improved analyze view for website conversion goals

The **Analyze goal** button for website conversion goals now correctly applies user‑defined filters in the Analyze view.

### JVM GC metrics

The 5-second rollups for JVM GC metrics are now correctly reported. Previously, the 5-second rollups for GC invocations and time used the average of the samples. They now use the sum of the samples. When you use Beeinstana, rollups that are greater than 5 seconds use the user-defined aggregation.

For alerting, 5-second rollups are used only in standard events. Smart alerts use the user-defined aggregation.

### Smart Alerts

Improved reliability of Smart Alerts to avoid false positives. Previously, Smart Alerts could be muted after a maintenance operation on the filler component. This fix aims to improve resiliency of Smart Alerts and avoid false positives.
