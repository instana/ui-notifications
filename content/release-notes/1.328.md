## Features

The following features are added in release 1.0.328:

### Adaptability and seasonality parameters for adaptive threshold

Adaptive threshold now supports configuring adaptability and seasonality parameters directly in the Smart Alert settings. Adaptability controls how quickly the threshold model responds to changes in your metrics. Seasonality lets you specify or override the detected seasonal pattern (none, daily, or weekly). These settings were previously available only as a private preview and are now generally available. The default adaptability value is decreased from 1.0 to 0.3.

For more information, see [Adaptive threshold](https://www.ibm.com/docs/en/instana-observability/standard/1.0.327?topic=instana-adaptive-thresholds-in-smart-alerts).

### Incident ID

When you create an incident, you can assign a unique incident ID to make it easier to reference the incident both within and outside the platform. The incident ID consists of an alphanumeric value that includes a customizable prefix that you define. After you enable and configure the prefix, the system automatically generates the numeric portion of the ID for each new incident.

The incident ID is included in incidents that are sent through the following outbound integrations:

- Bidirectional Microsoft Teams
- Bidirectional Slack
- Email
- Generic webhook
- ServiceNow

For more information, see [Incident ID](../../../pages/events_alerts/incident-ID.md).

### Log perspectives

Log perspectives are now available in Instana. You can create named, filtered views of log data and assign them to teams to help enforce role-based access control (RBAC).

Log perspectives include the following capabilities:

- **Log count**: View the number of log messages that match a perspective's filters within the selected time range.
- **Perspective management**: Create, view, edit, and delete log perspectives from **Logs** > **Log perspectives**. Bulk deletion is also supported.
- **Query support**: Filter log queries by `log.perspectiveIds` by using `tagFilterExpression` syntax to retrieve logs that are scoped to one or more perspectives.
- **Role-based permissions**: Only users with the **Create, configure, and delete log perspectives** permission can create log perspectives.
- **Sorting**: Sort perspectives by name or log count.

For more information, see [Role-based access control (RBAC) for logs](https://www.ibm.com/docs/en/instana-observability/saas?topic=logging-role-based-access-control-rbac-logs).

### Range operators for Smart Alert thresholds (applications, mobile app, and websites)

Smart Alerts for monitoring applications, mobile apps, and websites now support range operators for both static and adaptive thresholds. For static thresholds, you can use the **Between** operator to trigger an alert when a metric value falls within a configured range, or the **Outside** operator to trigger an alert when the metric value falls outside that range. For adaptive thresholds, you can use the **Outside** operator to trigger an alert when the metric value falls outside the predicted range.

For more information, see:
- [Smart Alerts for applications](../../application_monitoring/smart_alerts.md)
- [Smart Alerts for mobile apps](../../mobile_app_monitoring/smart_alerts.md)
- [Smart Alerts for websites](../../website_monitoring/smart_alerts.md)

## Improvements

The following improvements are provided in release 1.0.328:

### GenAI observability: Model and platform support on the Traces page

The **Traces** page now includes **Model** and **Platform** fields to help you identify the AI model and provider that are associated with each trace.

- The **Model** column displays the model identifier, such as `gpt-4o` or `granite-3-8b-instruct`.
- The **Platform** column displays the AI provider or framework, such as `openai`, `watsonx`, or `anthropic`.
- You can filter traces by **Model** and **Platform** from the filter panel.
- Active filter selections appear as removable filter tags.

By default, the **Model** and **Platform** columns are hidden. To display them, enable the columns from the **Configure columns** panel.

### GraphQL support for website and release data

GraphQL queries now support fetching data for website monitoring and Instana releases. For more information, see the [Instana GraphQL guides](https://developer.ibm.com/apis/catalog/instana--instana-graphql/Introduction) on IBM API Hub.

### Improved OpenTelemetry call correlation

OpenTelemetry calls now provide more accurate correlation with the associated Kubernetes container infrastructure.

### Power HMC temperature metrics in custom dashboards

You can now monitor inlet, CPU, and baseboard temperature metrics of Power HMC systems in custom dashboards. You can select temperature metrics for individual sensors when you configure a dashboard widget.

For more information, see [Managed system energy monitoring](https://www.ibm.com/docs/en/instana-observability/saas?topic=technologies-monitoring-power-hmc#managed-system-energy-monitoring).
