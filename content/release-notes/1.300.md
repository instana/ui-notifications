## Features

The following features are added in release 1.0.300:

### Infrastructure smart alert incidents

Instana now automatically identifies short-lived events that are likely to resolve on their own, helping reduce noise and alert fatigue. These transient events are labeled in the Events table and can be filtered from the event view. Alerts for transient events can also be temporarily muted until the event persists beyond a configured threshold.

The feature is enabled by default for each custom event, but users can fine-tune the behavior by adjusting the transient threshold, disabling the feature, or configuring alert suppression rules. This allows teams to focus on persistent issues while safely ignoring events that are too brief to act on. For more information, see [Transient Events Configurations](https://www.ibm.com/docs/en/instana-observability/1.0.300?topic=alerts-defining-custom-events) and [FAQ](https://www.ibm.com/docs/en/instana-observability/1.0.300?topic=alerts-defining-custom-events#faq).

### Infrastructure smart alert incidents

You can now configure infrastructure smart alerts to automatically trigger incidents. This feature enables event correlation and recommended actions for each incident that is generated by the smart alert. For more information, see [Infrastructure smart alerts](https://www.ibm.com/docs/en/instana-observability/current?topic=infrastructure-smart-alerts).

## Improvements

The following improvements are provided in release 1.0.300:

### OpenTelemetry

The OpenTelemetry calls are now improved to more accurately link to related infrastructure.

### OpenTelemetry collector support in UI

Instana now supports installing OpenTelemetry Collectors directly from the product UI, which makes setup and management easier than ever. The product introduces a dedicated page for OpenTelemetry Collectors that provides visibility into the health status of each collector and a unique collector ID. The scope of agents now includes OpenTelemetry Collectors, and collectively renamed as data sources for clarity.

## Fixes

The following issues are fixed in release 1.0.300:

### Infra Linking

Previously, calls created from the vertx.client span were not linked to a Kubernetes service. This issue is now fixed.

### Synthetic monitoring

- Security vulnerabilities CVE-2025-41234 and CVE-2025-47279 are fixed in Synthetic PoP.
- Security vulnerabilities CVE-2024-0406, CVE-2025-24882, CVE-2025-32386, and CVE-2025-32387 are fixed in the popctl tool.
