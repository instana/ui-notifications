## Features

The following features are added in build 292:

### Impacted users

A new feature, **Impacted Users**, is now available for application Smart Alerts. It helps you to identify widespread performance issues by tracking the number of users who are affected by the specific conditions. This feature provides the following capabilities:
- Prioritize fixes to address the issues that are impacting a large portion of users first.
- Use quantifiable data to justify resource allocation for improvements.
- Help developers focus on areas with the most frequent impact.

For more information, see [Smart Alerts](https://www.ibm.com/docs/en/instana-observability/current?topic=ma-smart-alerts#impacted-users).

### Parameterized custom dashboards (public preview)

You can use the filter bar of the dashboard to apply filters across all widgets within the dashboard. For more information, see [Parameterized custom dashboards](https://www.ibm.com/docs/en/instana-observability/current?topic=dashboards-parameterized-custom).

### Live action generation using watsonx.ai (public preview)

The real-time action creation feature enhances the automation capabilities of Instana. With the help of IBM's Granite generative AI models, you can now produce new actions. The metadata from incident and issue events prompts the AI model to suggest possible actions for you to examine and execute, aiding in accurate diagnosis and resolution. If you save an action, you can generate a bash script to carry out that action. This script, powered by generative AI, can serve as a manual or automated response to the current incident and future ones.
The actions you add to the action catalog help other Instana users in your organization as they seek to resolve similar incidents in the future. When you create actions with help from Action Generation using watsonx.ai, you further reduce the time to diagnose and resolve issues.
For more information, see [Live action generation with watsonx (public preview)](https://www.ibm.com/docs/en/instana-observability/current?topic=ma-intelligent-remediation-live-action-generation-watsonx-public-preview)

## Improvements

The following improvements are provided in build 292:

### Span processing

Previously, when a span attribute used an incorrect data type, the ingested tracing data was rejected. Now, the span processing is more lenient. Even if a span attribute uses an incorrect data type, the tracing data is still processed.

### OpenTelemetry

Instana now supports various deprecated span attributes to extract the HTTP host tag from OpenTelemetry HTTP spans. This improvement makes sure that the OpenTelemetry HTTP calls are mapped to the correct services instead of the `Unspecified` service.

### Alerts based on severity

You can now configure different alert channels for different severities in Smart Alerts for mobile applications, websites, and logs. Alert notifications are sent to different alert channels based on the severity of the issue.

### Thresholds for mobile applications, websites, and logs Smart Alerts

You can now set thresholds for the _warning_ and _critical_ severities in Smart Alerts for [mobile applications](https://www.ibm.com/docs/en/instana-observability/current?topic=applications-smart-alerts#alert-threshold), [websites](https://www.ibm.com/docs/en/instana-observability/current?topic=websites-smart-alerts#alert-threshold), and [logs](https://www.ibm.com/docs/en/instana-observability/current?topic=logging-smart-alerts#adding-an-alert).

### Synthetic monitoring

- Now you can monitor self-signed certificates with the SSLCertificate tests. For more information, see [No certificate error](https://www.ibm.com/docs/en/instana-observability/current?topic=monitoring-deploying-self-hosted-pop#No-certificate-error).
- Now Synthetic PoP uses Chromium 113.

### Support for monitoring DeepSeek models

Instana now supports monitoring of DeepSeek models. For more information, see [DeepSeek](https://www.ibm.com/docs/en/instana-observability/current?topic=platforms-deepseek).

## Fixes
This release resolves the following issues:


### Service mapping

Previously, when a call was made to the IP address 169.254.169.254 by explicitly using the default HTTP port 80 (for example, 169.254.169.254:80), the call was incorrectly mapped to the Unspecified service instead of the Cloud Metadata Service. This issue is resolved now.

### Synthetic monitoring
