## Features

The following features are added in build 292:

### Impacted users

A new feature, **Impacted Users**, is now available for application Smart Alerts. The feature helps you to identify widespread performance issues by tracking the number of users who are affected by the specific conditions. This feature tracks the number of users affected by specific conditions, which helps you to identify widespread performance issues.

This feature provides the following capabilities:

- Prioritize fixes to address the issues that impact many users first.
- Leverage quantifiable data to justify resource allocation for improvements.
- Assist developers focus on areas with the most frequent impact.

For more information, see [Smart Alerts](https://www.ibm.com/docs/en/instana-observability/current?topic=ma-smart-alerts#impacted-users).

### Incident Summarization using GenAI

Instana can now summarize incidents by using WatsonX. For more information, see [Incident AI Summarization (public preview)](https://www.ibm.com/docs/en/instana-observability/current?topic=alerts-incident-ai-summarization-public-preview).

### Live action generation using watsonx.ai (public preview)

The real-time action creation feature enhances the automation capabilities of Instana. With the help of IBM's Granite generative AI models, you can now produce new actions. The metadata from incident and issue events prompts the AI model to suggest possible actions for you to examine and execute, aiding in accurate diagnosis and resolution. If you save an action, you can generate a bash script to carry out that action. This script, powered by generative AI, can serve as a manual or automated response to the current incident and future ones.
The actions you add to the action catalog help other Instana users in your organization as they seek to resolve similar incidents in the future. When you create actions with help from Action Generation using watsonx.ai, you further reduce the time to diagnose and resolve issues.
For more information, see [Live action generation with watsonx (public preview)](https://www.ibm.com/docs/en/instana-observability/current?topic=ma-intelligent-remediation-live-action-generation-watsonx-public-preview).

### Parameterized custom dashboards (public preview)

You can use the filter bar of the dashboard to apply filters across all widgets within the dashboard. For more information, see [Parameterized custom dashboards](https://www.ibm.com/docs/en/instana-observability/current?topic=dashboards-parameterized-custom).

### Save filters

Instana now allows users to save, edit, and delete filters on the Analytics page, which improves filter management and usability.

### Service levels (GA)

Service-level objectives (SLOs) v2 are now generally available. They exceed the capabilities or the original Custom Dashboard only Service Level Indicators, which they will eventually replace.
SLOs are important observability tools that are used to monitor performance and availability of services in a systematic and objective way. You define clear performance targets to help identify degraded user experience and platform instability.
- Set objectives for latency, availability, traffic levels, or custom event counts
- Apply SLOs to applications, websites, or Synthetic Monitoring test results for service availability
- Track the error budget as it changes over the SLO time window and generate alerts as it approaches user-defined thresholds or increased burn rate
- Embed SLO charts and Big Number indicators into Custom Dashboards
  Use key SLOs to represent the level of performance and availability your users expect from your services. You can then focus on issues, knowing that resolving them have a direct impact on the user experience.

## Improvements

The following improvements are provided in build 292:

### Alerts based on severity

You can now configure different alert channels for different severities in Smart Alerts for mobile applications, websites, and logs. Alert notifications are sent to different alert channels based on the severity of the issue.

### Long-term trace storage

In the Trace Detail view on the **Analytics** dashboard, you can now store the displayed trace for long term. To store the trace, click the **Store Trace** button to manually store the displayed trace. Alternatively, you can also store the trace automatically by staying on the Trace Detail view for at least 15 seconds. However, storing large traces for long term is not possible.

### OpenTelemetry

Instana now supports various deprecated span attributes to extract the HTTP host tag from OpenTelemetry HTTP spans. This improvement makes sure that the OpenTelemetry HTTP calls are mapped to the correct services instead of the `Unspecified` service.

### Service levels

Service-level objectives dashboards now show Indicator charts that contain data from the Indicator for time-based SLOs, rather than directly from the resource. This aligns the representation of the Indicator with the Error Budget chart.

Instana now supports Terraform for configuring and managing Service Level Objectives assets.

### Span processing

Previously, when a span attribute used an incorrect data type, the ingested tracing data was rejected. Now, the span processing is more lenient. Even if a span attribute uses an incorrect data type, the tracing data is still processed.

### Support for monitoring DeepSeek models

Instana now supports monitoring of DeepSeek models. For more information, see [DeepSeek](https://www.ibm.com/docs/en/instana-observability/current?topic=platforms-deepseek).

### Synthetic monitoring

- Now you can monitor self-signed certificates with the SSLCertificate tests. For more information, see [No certificate error](https://www.ibm.com/docs/en/instana-observability/current?topic=monitoring-deploying-self-hosted-pop#No-certificate-error).
- Now Synthetic PoP uses Chromium 113.

### Thresholds for mobile applications, websites, and logs Smart Alerts

You can now set thresholds for the _warning_ and _critical_ severities in Smart Alerts for [mobile applications](https://www.ibm.com/docs/en/instana-observability/current?topic=applications-smart-alerts#alert-threshold), [websites](https://www.ibm.com/docs/en/instana-observability/current?topic=websites-smart-alerts#alert-threshold), and [logs](https://www.ibm.com/docs/en/instana-observability/current?topic=logging-smart-alerts#adding-an-alert).

## Fixes
This release resolves the following issues:

### Meta widget overflow

Previously, the content of the Meta widget in the Trace Detail view on the **Analytics** dashboard overflowed. This issue is now fixed.

### Service mapping

Previously, when a call was made to the IP address 169.254.169.254 by explicitly using the default HTTP port 80 (for example, 169.254.169.254:80), the call was incorrectly mapped to the unspecified service instead of the Cloud Metadata Service. This issue is now resolved.

### Synthetic monitoring

The following security vulnerabilities are fixed in Synthetic PoP:

- CVE-2023-22081
- CVE-2024-38820
- CVE-2024-57699
- CVE-2024-38827
- CVE-2023-5590
