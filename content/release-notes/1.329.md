## Features

The following features are added in release 1.0.329:

### Conversion funnels for websites

Instana now supports defining and tracking conversion funnels for websites. Use conversion funnels to track user actions across multiple steps and identify where users drop off in the flow.

For more information, see [Business impact for websites](../../website_monitoring/business_impact.md) and [Conversion funnels for websites](../../website_monitoring/conversion_funnels.md).

### Conversion goals for mobile apps

Instana now supports defining and tracking conversion goals for mobile apps.

For more information, see [Business impact](../../website_monitoring/business_impact.md) and [Conversion goals for mobile apps](../../mobile_app_monitoring/conversion_goals.md).

### Enabling and disabling automation policies

You can now enable or disable an automation policy from the **State** column of the policy table on the **Policies** tab. Disabling a policy pauses it until you enable it again.

For more information, see [Enabling and disabling a policy](../../automation/automation-policies.md#enabling-and-disabling-a-policy).

### Range operators for Smart Alert thresholds in Generative AI Observability

Smart Alerts for Generative AI Observability now support range operators for both static thresholds. You can use the **Between** operator to trigger an alert when a metric value falls within a configured range, or the **Outside** operator to trigger an alert when the metric value falls outside that range.

For more information, see [Creating Smart Alerts for Generative AI applications](../../gen-ai-observability/guides/smart-alerts/index.md).

### Simulate network conditions in browser synthetic script tests

Browser synthetic script tests that run on Google Chrome now support configurable network profiles. You can simulate Offline, 3G, Slow 4G, and Fast 4G network conditions to evaluate application behavior and performance across different connectivity scenarios.

You must upgrade the Synthetic PoP to version 1.2.62 to use the new network profiles.

### SLO health dashboard

The SLO health dashboard is available on the **SLO summary** tab and provides a system-wide view of service level objective (SLO) health across your monitoring environment. The dashboard displays key performance indicator (KPI) summary cards and a chart that shows the number of SLOs in each health state: **Total**, **Healthy**, **At risk**, **Breached**, and **Insufficient data**. Selecting a health state filters the SLO list to display only SLOs in that state.

The **SLO summary** tab is the first tab on the **Service Levels** page. The SLO list is on the **SLOs** tab. Instana automatically redirects previously saved or bookmarked URLs, so you do not need to update them.

For more information, see [Service level objectives](../../service_level_objectives/slo_capabilities.md).

### Support for ECMAScript modules in browser synthetic script tests

Browser synthetic script tests now support ECMAScript modules (ESM). You can use JavaScript module syntax, including `import` and `export` statements, in single-file and bundled browser scripts. You can enable ESM support by using a script pragma or by using `.mjs` files, which simplifies the development and maintenance of browser synthetic tests.

You must upgrade the Synthetic Point of Presence (PoP) to version 1.2.62 to use the new ESM support.

For more information, see [ESM browser testing scripts](../../synthetic_monitoring/browser_script/overview.md#browser-scripts-esm-browser-testing-scripts).

## Improvements

The following improvements are provided in release 1.0.329:

### Delta counters for Cilium monitoring (public preview)

Cilium dashboards use delta counters to display Cilium metrics. The `k8sensor` calculates the change in each counter value between collection cycles and sends only the delta values to the Instana backend. The `k8sensor` omits metric series with no change, which reduces the volume of transmitted data. To display Cilium graphs correctly, use `k8sensor` 1.4.33 or later, together with Instana backend and `ui-client` 1.0.329 or later.

For more information, see [Monitoring Cilium](../../ecosystem/kubernetes/cilium-monitoring.md).

### Improved endpoint mapping for versioned HTTP paths

When Instana creates an endpoint name from the first segment of an HTTP path, it now skips the leading `/{version}/api/` prefix. Instana takes the first segment from the part of the path that follows the prefix, so versioned APIs are grouped into meaningful endpoints. For example, Instana maps the call `GET /v1.3.0/api/foo/123` to the endpoint `GET /v1.3.0/api/foo`.

### Support for migrating from a Slack alert channel to an App for Slack alert channel

Slack alert channels rely on a legacy custom Slack integration that is being deprecated. Instana recommends that you migrate to the App for Slack alert channel, which uses an app-based integration.

For more information, see [Migrating from Slack to App for Slack alert channel](../../ecosystem/slack/migrate-slack-app.md) and [App for Slack alert channel](../../ecosystem/slack-app/index.md).
