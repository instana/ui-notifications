## Features

The following features are added in release 1.0.329:

### Enabling and disabling automation policies

You can now enable or disable an automation policy from the **State** column of the policy table on the **Policies** tab. Disabling a policy temporarily pauses it from running.

For more information, see [Enabling and disabling a policy](../../automation/automation-policies.md#enabling-and-disabling-a-policy).

### SLO health dashboard

The SLO health dashboard is available on the **SLO summary** tab and provides a system-wide view of SLO health across your monitoring environment. The dashboard displays KPI summary cards and a chart showing the number of SLOs in each health state: **Total**, **Healthy**, **At risk**, **Breached**, and **Insufficient data**. Selecting a health state filters the SLO list to display only SLOs in that state. 
The **SLO summary** tab is the first tab on the **Service Levels** page. The SLO list is on the **SLOs** tab. Previously saved or bookmarked URLs are redirected automatically, so you do not need to update them.

### Allow the use of ECMAScript modules in browser synthetic script tests

Browser synthetic script tests now support ECMAScript modules (ESM). You can use JavaScript module syntax, including import and export statements, in single-file and bundled browser scripts. You can enable ESM support by using a script pragma or by using .mjs files, which simplifies the development and maintenance of browser synthetic tests.

You must upgrade the Synthetic PoP to version 1.2.62 to use the new ESM support.

### Simulate network conditions in browser synthetic script tests

Browser synthetic tests that run on Google Chrome now support configurable network profiles. You can simulate Offline, 3G, Slow 4G, and Fast 4G network conditions to evaluate application behavior and performance across different connectivity scenarios.

You must upgrade the Synthetic PoP to version 1.2.62 to use the new network profiles.

## Improvements

The following improvements are provided in release 1.0.329:

### Improved endpoint mapping for versioned HTTP paths

When an endpoint name is created from the first segment of an HTTP path, the leading `/{version}/api/` prefix is now skipped. The first segment is taken from the part of the path that follows the prefix, so versioned APIs are grouped into meaningful endpoints. For example, the call `GET /v1.3.0/api/foo/123` is mapped to the endpoint `GET /v1.3.0/api/foo`.

### Delta counters for Cilium monitoring (public preview)

Cilium dashboards use delta counters to display Cilium metrics. The `k8sensor` calculates the change in each counter value between collection cycles and sends only the delta values to the Instana backend. Metric series with no change are omitted, reducing the volume of data transmitted. To display Cilium graphs correctly, use `k8sensor` 1.4.33 or later, and Instana backend and `ui-client` 1.0.329 or later. For more information, see [Monitoring Cilium](../../ecosystem/kubernetes/cilium-monitoring.md).
