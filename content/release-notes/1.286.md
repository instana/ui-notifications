# Build 286

2024-11-18

## Features
### Limited access RBAC for Business Monitoring
You can now select the **Limited access** permission scope for **Business Monitoring** while managing user groups.
Users in a group with limited access can view only the business perspectives and processes to which they are explicitly granted access to.
For more information, see [Manage user access](https://www.ibm.com/docs/en/instana-observability/current?topic=instana-managing-user-access#business-monitoring).

### Synthetic monitoring new metrics API
A new Synthetic monitoring endpoint is available to retrieve metrics of Synthetic test results.
With this API, you can group the results by tags other than the Synthetic test ID.
By default, the test results are grouped by test ID.
For more information, see [OpenAPI](https://instana.github.io/openapi/#operation/getMetricsResult).

### Threshold on table widget
You can add a threshold to the table widget in a custom dashboard to highlight values that exceed or fall under certain levels.
Setting a threshold adds a visual color-coded indicator for metrics and helps spot warning and critical values.
For more information, see [Setting a threshold to widgets in custom dashboard](https://www.ibm.com/docs/en/instana-observability/current?topic=dashboards-adding-threshold-big-number-widget)

## Improvements
### Monitoring large language models
The large language model (LLM) monitoring now supports the following features:
  * Monitoring of AWS Bedrock applications
  * Log monitoring for LLM applications
  * Agentless ingestion for OpenTelemetry (OTel) Data Collector to send data directly to the Instana backend

For more information, see [Monitoring LLMs](https://www.ibm.com/docs/en/instana-observability/current?topic=technologies-monitoring-llms).

### The *Access Control* and *Audit* options are moved
The **Team Settings** tab in the **Settings** menu is renamed as **Global Settings**.
The following options are moved from the **Team Settings** tab to the **Security & Access** tab:
* **Access Control**
* **Audit**
* **Identity Providers**
* **Session**

For more information on the **Access Control** and **Audit** options, see [Manage Users](https://www.ibm.com/docs/en/instana-observability/current?topic=instana-managing-user-access). 
For more information on the **Identity Providers** and **Session** options, see [Authentication](https://www.ibm.com/docs/en/instana-observability/current?topic=instana-configuring-authentication).

## Breaking changes
### Agent Helm chart v2.0.2
The Agent Helm chart was released in version 2.0.2.
The main change in the 2.x branch is the installation of a Kubernetes operator.
The Kubernetes operator handles all Agent and k8s-sensor resources in a Kubernetes and OpenShift cluster.
Agent and Kubernetes-sensor resources are configured by a CustomResourceDefinition (CRD), which is now part of the Helm install.

#### Helm install
Initial installation of the Instana agent with Helm is the same in version 1.x and version 2.x.
For more information, see [Install by using the Helm chart](https://www.ibm.com/docs/en/instana-observability/current?topic=kubernetes-installing-agent#install-by-using-the-helm-chart).

Red Hat OpenShift requires a slightly different set of commands for Helm installation.
For more information, see [Installing by using the Helm chart](https://www.ibm.com/docs/en/instana-observability/current?topic=openshift-installing-agent-red-hat#installing-by-using-the-helm-chart).

#### Helm upgrade
The upgrade method for an existing Helm-based installation is changed.
You must use an intermediate command to apply the CRD to the cluster.
For more information on installing the agent with Helm chart, see [Install by using the Helm chart](https://www.ibm.com/docs/en/instana-observability/current?topic=kubernetes-installing-agent#install-by-using-the-helm-chart).

Red Hat OpenShift requires a slightly different set of commands to update the Helm chart.
For more information, see [Updating a Helm chart installation](https://www.ibm.com/docs/en/instana-observability/current?topic=openshift-administering-agent-red-hat#updating-a-helm-chart-installation).

#### Helm uninstall
Uninstalling Instana resources requires a different set of commands.
For more information, see [Agents installed by using the Helm chart](https://www.ibm.com/docs/en/instana-observability/current?topic=kubernetes-uninstalling-agent#agents-installed-by-using-the-helm-chart).

Red Hat OpenShift requires a slightly different set of commands to uninstall Instana resources.
For more information, see [Uninstalling the host agent that is installed by using Helm chart](https://www.ibm.com/docs/en/instana-observability/current?topic=openshift-uninstalling-agent-red-hat#uninstalling-the-host-agent-that-is-installed-by-using-helm-chart).
