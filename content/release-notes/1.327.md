## Features

The following features are added in release 1.0.327:

### Log perspectives

You can now create log perspectives to define filtered subsets of log data and enforce role-based access control on them. A log perspective acts as a scoped view of logs that you can assign to specific teams. Team members can view only the logs within the perspectives assigned to their team.

To get started, create a log perspective in **Logs** > **Log perspectives**, and then assign it to a team in **Settings** > **Security & Access** > **Teams**. For more information, see [Create a log perspective](https://www.ibm.com/docs/en/instana-observability/saas?topic=logging-role-based-access-control-rbac-logs#log-perspectives-public__title__1).

When you assign a team to a log perspective, Instana no longer applies the role-based access control previously enforced through application perspectives to that team. Configure your log perspectives correctly before you assign teams to avoid gaps in access control.
{: important}

For more information, see [Role-based access control (RBAC) for logs](https://www.ibm.com/docs/en/instana-observability/saas?topic=logging-role-based-access-control-rbac-logs).
## Improvements

The following improvements are provided in release 1.0.327:

### Kubernetes Cluster Name tag for OpenTelemetry calls

OpenTelemetry calls that are linked to a Kubernetes Pod infrastructure entity now include the **Kubernetes Cluster Name** tag.

### Stack view

OpenTelemetry Kubernetes entities, previously listed under the **Infrastructure** section, are now grouped under the **Kubernetes** section.
