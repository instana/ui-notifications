## Features

The following features are added in release 1.0.310:

### Conversion goals for websites

Instana now supports defining and tracking conversion goals for websites.

For more information, see [Business impact](https://www.ibm.com/docs/en/instana-observability/saas?topic=websites-business-impact) and [Conversion goals for websites](https://www.ibm.com/docs/en/instana-observability/saas?topic=impact-conversion-goals).

### Dependency view for websites and mobile applications

Instana provides a clear view of direct service dependencies for websites and mobile applications. The **Dependency** tab displays both graph and table views, showing the services that each application calls with key metrics, such as call volume, error rate, and average latency. In addition, you can view the detected issues that are highlighted at the website or service level, including their severity.

For more information, see [Websites dependency](https://www.ibm.com/docs/en/instana-observability/saas?topic=instana-monitoring-websites#concept_2__title__1) and [Mobile app dependency](https://www.ibm.com/docs/en/instana-observability/saas?topic=instana-monitoring-mobile-applications#concept_1__title__1).

### Instana AI Gateway (public preview)

Instana now supports LLM gateways for connecting to watsonx.ai or vLLM-compatible services such as Red Hat AI Inference Server. By configuring an LLM gateway with credentials for your AI inference service, you can enable Instana’s gen AI capabilities such as AI assistant, incident summarization, incident investigation, and action or script generation. This flexibility is essential for self-hosted deployments where inference engines run outside Instana. You can customize LLM gateways by selecting Granite or Mistral as the LLM model and setting performance parameters that are secured with RBAC controls.

For more information, see [LLM gateways](https://www.ibm.com/docs/en/instana-observability/saas?topic=instana-ai-gateway-public-preview).

### Intelligent incident investigation

You can now run an agentic investigation on Instana incidents with probable root cause analysis. To begin running this investigation, go to the Incidents dashboard, and from the Explore probable root cause section of the details view for an incident, click Run investigation.

Access to this feature is for all customers in SaaS regions. For more information, see [Intelligent incident investigation](https://www.ibm.com/docs/en/instana-observability/saas?topic=capabilities-intelligent-incident-investigation).

### Process environment variables as tags

For self-hosted installations, you can use environment variables as tags for process entities. For more information, see [Adding environment variables as tags for process entities](https://www.ibm.com/docs/en/instana-observability/saas?topic=configuring-enabling-optional-features#process-environment-variables__title__1).

### Service level objectives

**Saturation golden signal for infrastructure entities:** Service Level Objectives (SLOs) now support the saturation golden signal, you can monitor resource usage and capacity for infrastructure entities. You can create SLOs based on metrics, such as CPU usage, memory consumption, and other resource saturation indicators for hosts, Kubernetes clusters, and other infrastructure components, with support for both time-based and event-based indicators. For more information, see [Service level objectives](https://www.ibm.com/docs/en/instana-observability/saas?topic=slos-service-level-objectives).

**Kubernetes SLO integration:** You can now view SLOs at both the Kubernetes platform level and within individual clusters. The **SLO** tab filters results by context, and the creation flow offers a streamlined process for defining Kubernetes-specific SLOs.

### Sensor custom extension (public preview)

You can now collect custom metrics from IBM Db2, IBM MQ, and Oracle DB beyond the standard metrics. Define custom metric entities in the agent configuration file to specify which performance metrics to collect, set polling intervals, and add custom tags or labels. The sensor custom extension automatically generates the appropriate queries and exports all metrics in the Prometheus format.

For more information, see [IBM Db2](https://www.ibm.com/docs/en/instana-observability/saas?topic=technologies-monitoring-db2#configuring-sensor-custom-extension-public-preview__title__1), [IBM MQ](https://www.ibm.com/docs/en/instana-observability/saas?topic=mq-configuring#configuring-sensor-custom-extension-public-preview__title__1), and [Oracle DB](https://www.ibm.com/docs/en/instana-observability/saas?topic=technologies-monitoring-oracledb#configuring-sensor-custom-extension-public-preview__title__1).

### Widgets on Custom dashboard for Synthetic monitoring

Now you can use the following widgets on Custom dashboard to visualize metrics for Synthetic monitoring.
* Big number
* Pie chart
* Table
* Time series chart
* Top list 

For more information, see [Synthetic monitoring](https://www.ibm.com/docs/en/instana-observability/saas?topic=dashboards-synthetic-monitoring).

## Improvements

The following improvements are provided in release 1.0.310:

### Azure App Service agent installation

The Azure App Service agent installation now includes a script-based installation for automating deployments on Windows hosts.

### Bulk delete for Synthetic tests

You can now delete multiple tests on the **Synthetic tests** page.

### Helm and Linux s390 support for OTEL Collector installation

You can now install the OpenTelemetry Collector by using Helm or on the Linux s390 platform directly from the Instana UI. Previously, these installations required following external documentation. Now the Instana UI automatically displays the appropriate installation commands.

### SAP Java NetWeaver sensor

The SAP Java NetWeaver sensor is now generally available. For more information, see [Monitoring SAP with the Java NetWeaver sensor](https://www.ibm.com/docs/en/instana-observability/saas?topic=sap-monitoring-java-netweaver-sensor)

### Service level objectives creation flow

The SLO creation flow is redesigned as a multi-step approach, providing an improved user experience with enhanced visual consistency and usability.

## Fixes

The following issues are fixed in release 1.0.310:

### Service level objectives

SLO and Service-Level indicators (SLI) data sources are now restricted to supported widget types. Previously, the data source was available for unsupported widgets, such as pie charts and line charts, which could cause unexpected behavior. The data source is now limited to native SLO widgets and big number widgets.

### Synthetic monitoring

The following security vulnerabilities are fixed on Synthetic PoP:
- CVE-2025-30698
- CVE-2025-54798
- CVE-2025-56200
- CVE-2025-64118
- CVE-2025-64718
- CVE-2025-64756
